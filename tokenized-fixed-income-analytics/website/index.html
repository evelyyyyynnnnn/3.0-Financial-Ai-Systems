Data

Every figure comes from a synthetic on-chain history generated by src/chain.py, built so each measure can be checked against a property that was deliberately put there. No real chain data is used, and the absolute levels below carry no information about any real token.

What can be measured from a chain

Tokenised debt does not trade every minute and has no consolidated order book, so anything needing a regular grid or quote depth is unusable. Every measure here works from two inputs a chain actually provides: a trade tape and a holder snapshot.

Concentration is reported as effective holders (1/HHI) rather than as an index. An HHI of 0.05 means the float behaves as though held by twenty equal holders, however many wallets appear on chain — and wallet count is exactly the number that misleads, since one holder can hold many wallets and often does.

Liquidity

This measure was inverted until the generator was fixed

The first version of the chain model drew every token's per-trade return from the same distribution, so order size carried no price impact. Amihud is a price-impact measure, so with no impact to find it read pure noise — and ranked the thinnest token in the universe as the most liquid.

Giving each token a depth parameter, so the same order moves a thin token further, restored the ordering shown above: it now runs monotonically from STABLE-X at 0.060 to MUNI-A at 0.546. A metric that cannot recover a property you deliberately built is not measuring that property, and this is the check that caught it.

Roll's spread is estimated from the autocovariance of price changes. When that autocovariance comes out positive the bid-ask-bounce model does not apply, and the function returns n/a rather than a fabricated number — which happens in strongly trending markets and is a real limitation of the estimator.

Concentration

Sweeping the Pareto tail parameter and confirming the measure moves with it is the concentration equivalent of the Amihud check. It is monotone across the sweep (confirmed), so the index is tracking the thing it is named after.

Why this is the measure that matters

For a debt token, the queue lengthening is what turns a liquidity problem into a run, and it is invisible in the price. Across the tokens with a stress episode, median settlement latency rises by a factor of 5.2 while the tape keeps printing.

STABLE-X has no stress episode in the generator and shows a ratio near 1, which is the control: a measure that fired on it would be responding to something other than stress.

Reproduce it

cd tokenized-fixed-income-analytics
pip install -r requirements.txt
python -m pytest tests/ -q
python -m src.demo

To run on real data, replace src/chain.py with a loader returning TokenHistory objects from an indexer. Nothing in src/analytics.py changes.

What this does not establish

  • No real token has been analysed. The generator was written to exhibit the properties the measures look for, so agreement between them is a soundness check on the code, not a finding about any market.
  • Holder concentration from wallet balances is a lower bound on true concentration. One beneficial holder can hold many wallets, and nothing on chain distinguishes that from many holders.
  • Redemption latency here is generated, not observed. Real settlement depends on the issuer's operational process, which is off chain and mostly unobservable.
  • No regulatory or systemic-risk conclusion follows from synthetic data.
