# Measured Results

> Every figure the portfolio can actually support, read from the file each project's own demo wrote — and every claim it cannot.

**Repository:** `3.0-Financial-Ai-Systems` &middot; **Pillar:** Financial Stability

## Status

Working code with a runnable demo and 15 tests.

The roll-up walks the five repositories and reads each project's
`results/latest.json` (preferring `latest-real.json` where one exists). A number
with no run behind it cannot appear here, and a project that has never been run
is listed as such rather than quietly omitted.

As of the last run it covers **22 projects**, of which **19 report a run on real
data** and 3 are labelled synthetic or authored. The roll-up's own
`is_synthetic` stays `true`: it has no data source beyond the other projects'
result files.

It also carries the part that matters most for an outside reader —
`results/README.md` sets each claim made elsewhere against what this portfolio
can actually show, including the ones it cannot.

See `results/README.md` for the run date and the full table.

## Quick start

```bash
pip install -r requirements.txt
python -m pytest tests/ -q     # 15 tests
python -m src.demo             # runs everything, rewrites results/ and website/
```

```

  |-- latest.json

  |-- collect.py
  |-- demo.py
  |-- report.py
  |-- rollup.py
  |-- site.py
  |-- sitekit.py
tests/
  |-- .gitkeep
  |-- test_rollup.py
website/
  |-- README.md
  |-- index.html
  |-- results.json
  |-- vercel.json
```

- `src/` &mdash; the implementation.
- `tests/` &mdash; pytest suite. These guard behaviour, not just imports.
- `results/latest.json` &mdash; the output of the last demo run. Every figure quoted
  anywhere in this project traces back to this file.
- `website/` &mdash; a self-contained static site, deployable to Vercel by copying the
  folder into its own repository. See `website/README.md`.

## The website

`website/` has no build step. To deploy it independently:

```bash
cp -r website/ ../my-7-portfolio-results-rollup-site && cd ../my-7-portfolio-results-rollup-site
git init && git add -A && git commit -m "site"
vercel deploy --prod
```

The page is regenerated from `results.json` on every `python -m src.demo`, so the
figures on the site and the figures the code produces cannot drift apart. Do not edit
numbers on the page by hand.

## Honesty note

This project measures nothing of its own; it reports what other runs recorded,
including the runs whose result is poor, and it does not verify any project's
method. Its own result file is therefore labelled `is_synthetic: true`.

`results/README.md` lists every claim the wider application makes that this
portfolio cannot fully support. That table is the point of the project. A claim
marked *partially addressed* or *not evidenced* must not be cited to these
repositories.
